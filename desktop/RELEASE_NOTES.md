Portal Desktop 0.1.0：首个正式发布版

- Portal 通过 Git 子模块引用 `d5z/heart-portal` 的客户端兼容分支，随客户端编译、打包与发布。源码锁定至 383d915396aef8f7bc1e91e2127271d704288217，内置 Portal 0.8.2。
- macOS 提供签名 DMG，可将 Portal Desktop 拖入 Applications 安装；同一 GitHub Release 同时发布升级用 ZIP 和两种格式的 SHA-256 校验值。
- “检查更新 → 下载并升级”：先下载并校验，再点击“停止 Portal 并安装”。确认旧 Portal 和对应守护全部退出后，才关闭和替换客户端。
- macOS 自动备份并替换应用，Windows 使用 Setup；安装完成自动打开新版客户端，使用原配置、凭据、工作目录与 Kits 启动新引擎和守护。
- 兼容旧客户端服务和独立 Portal 并存，停止通过原管理协议执行；失败保留恢复记录，安装未完成时重新打开旧客户端可恢复运行。
- Portal 兼容分支保持客户端管理的运行目录，macOS / Windows 均提供连接状态；引擎不绕过客户端单独升级。
- 首次启动显示 loading，配置与升级恢复完成后才进入界面；Being 连接验证失败时仅启动客户端，保留原配置和待恢复记录。
- 原配置不改写，升级成功后运行本次客户端安装包配套的 Portal；升级期间本机任务会中断且不会重放。

请先完成本机任务并保存草稿。旧客户端尚无新升级入口时，退出后手动替换 macOS 应用或运行 Windows Setup，再打开新版；首次启动会完成 Portal 配套迁移。

macOS ARM64 的完整客户端及内置 Portal 采用与 Portal 源仓相同的 D5 Developer ID 签发，保留固定标识、Hardened Runtime 和安全时间戳；公证按源仓策略暂缓。Windows x64 尚未配置 Authenticode。请从本仓库下载，SHA256SUMS.txt 用于包完整性核对。

- macOS 在停止旧服务前检查完整应用签名、版本、架构和 Portal 摘要；损坏包、不可写安装位置与临时转移目录会提前报错，取消安装会清理暂存文件。
- 更新检查仅在对应平台安装包及校验清单齐备时提供安装入口。
- 升级后保留前台或后台运行设置；关闭后台常驻的客户端不会因此启用登录守护。
